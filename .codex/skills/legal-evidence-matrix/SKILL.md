# Legal Evidence Matrix

Create a table before creating a theory.

## Core rules

- Every row must tie back to a real source.
- Keep source paths and dates visible.
- Short quotes are better than paraphrased certainty.
- Mark missing information instead of guessing.

## Good matrix columns

- Source ID
- Date
- Source type
- Issue lane
- Speaker / author
- Key quote
- Why it matters
- Claim supported
- Contradiction or admission
- Authentication status
- Follow-up needed

## Best use cases

- Exhibit indexes
- Mediation prep tables
- Contradiction charts
- Discovery planning
- Witness prep
- Damages support tables

## Workflow

1. Gather the source set.
2. Normalize dates and source names.
3. Assign each source to one or more issue lanes.
4. Capture the key quote or factual nugget.
5. Mark whether it supports:
   - chronology
   - admission
   - contradiction
   - damages
   - authentication
6. Flag what is still missing.

## Output rules

- Keep the table deterministic and citation-friendly.
- Use `Unknown` or `[Needs Evidence]` when a row cannot be completed.
- Do not bury authentication problems.
